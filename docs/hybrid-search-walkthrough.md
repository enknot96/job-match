# ハイブリッド検索の動作ウォークスルー

`app/api/match/route.ts` が、1リクエストを受けてから「ベクトルのみ」と「ハイブリッド」の
2つのランキングを返すまでを、具体例で追った解説です。コードのコメントから切り出しました。

## 登場人物（DBの中身・簡略版）

| id | 名前 | 経歴 |
|----|------|------|
| 1 | 佐藤 | React/TS + AWS認定 |
| 2 | 田中 | React/TS（認定なし） |
| 3 | 森 | SRE/インフラ + AWS認定 |
| 4 | 渡辺 | Python（無関係） |

リクエスト: `{ "jobDescription": "Reactフロントエンド", "keywords": "AWS認定" }`

## ステップ

1. **リクエスト受信** — `jobDescription = "Reactフロントエンド"` / `keywords = "AWS認定"`
2. **求人要件をベクトル化** — Gemini で数値化し `vecStr = "[0.12,0.88,...]"`
3. **キーワード決定** — `keywords` があるので `ftsText = "AWS認定"`
4. **ベクトル検索**（意味が近い順）— 森(3)はインフラ職で意味が遠く入らない
   → `vecRows = [{id:2},{id:1},{id:4}]`（田中→佐藤→渡辺）
5. **全文検索**（"AWS認定" を含む）— 田中(2)・渡辺(4)は持たず入らない
   → `ftsRows = [{id:3},{id:1}]`（森→佐藤）

   ✋ ポイント: ベクトルには森がいない／全文には田中・渡辺がいない。**2つの検索の顔ぶれが違う**。

6. **id配列化** — `vecIds = [2,1,4]` / `ftsIds = [3,1]`
7. **ヒット判定用の集合** — `hitVec = {2,1,4}` / `hitFts = {3,1}`（後で `hitVec.has(3)` 等で照会）
8. **RRF 融合** — `score(id) += 1 / (K + 順位)`（K=60, 順位は0始まり）

   ベクトル側 `[2,1,4]`:

   | 誰 | i | 計算 | score |
   |----|---|------|-------|
   | id=2 | 0 | 1/61=0.0164 | 2→0.0164 |
   | id=1 | 1 | 1/62=0.0161 | 1→0.0161 |
   | id=4 | 2 | 1/63=0.0159 | 4→0.0159 |

   全文側 `[3,1]`:

   | 誰 | i | 計算 | score |
   |----|---|------|-------|
   | id=3 | 0 | 1/61=0.0164 | 3→0.0164 |
   | id=1 | 1 | 0.0161 + 1/62 = 0.0322 | 1→0.0322（合算） |

   完成した score:
   - `1 → 0.0322`（佐藤：両方にいたので2回加算＝最高得点）
   - `2 → 0.0164`（田中：ベクトルのみ）
   - `3 → 0.0164`（森：全文のみ）
   - `4 → 0.0159`（渡辺：ベクトルのみ・下位）

   `?? 0` の意味: 初登場は0から、2回目は既存値に足す → **両方ヒットが合算され、森のような人も拾える**。

9. **ハイブリッド上位確定** — score降順に並べ TOP件 → `hybridIds = [1,2,3,4]`（佐藤→田中→森→渡辺）
10. **比較用：ベクトルのみ上位** — `vectorOnlyIds = [2,1,4]`（田中→佐藤→渡辺。**森がいない**）
11. **本文取得** — `needIds = [1,2,3,4]` をまとめて SELECT し `byId` 早見表を作る
12. **表示用整形（build）** — 各idに score / hitVector / hitKeyword を付与

    ハイブリッド `build([1,2,3,4])`:

    | id | name | score | hitVector | hitKeyword |
    |----|------|-------|-----------|------------|
    | 1 | 佐藤 | 0.0322 | ✅ | ✅ |
    | 2 | 田中 | 0.0164 | ✅ | ❌ |
    | 3 | 森 | 0.0164 | ❌ | ✅ ← 救済 |
    | 4 | 渡辺 | 0.0159 | ✅ | ❌ |

13. **両方返す** —
    - vectorOnly（左）= 田中, 佐藤, 渡辺 … 森がいない
    - hybrid（右）= 佐藤, 田中, 森, 渡辺 … **森が復活**

## 結論

「意味で探したリスト」と「キーワードで探したリスト」を、id ごとに点数を足し合わせて1つにまとめる。

- **Set** = 「その人どっちにいた？」を聞く名簿
- **Map** = 「id→点数」の集計表
- **`?? 0`** = 初登場は0から、2回目は足し算 → 両方ヒットが高得点＝森のような人も拾える
